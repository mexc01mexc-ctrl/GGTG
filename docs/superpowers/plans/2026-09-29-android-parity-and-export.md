## 2. Ключевая идея экспорта для Android

Сейчас цепочка такая: Mac дублирует сессию → пишет tdata → Android берёт ключ из tdata и
**ещё раз** дублирует (handoff). Итог: лишняя активная сессия, лишний логин,
повторный запрос 2FA, и прокси/папка теряются.

Новый формат `*.ggtg` (zip) даёт прямую установку:

```
export.ggtg
└── manifest.json      # формат, дата и все аккаунты: userId, phone, имя, mainDcId,
                       # ключи {dcId, hex}, прокси, папка, pinned, 2FA

```

- Mac: для каждого аккаунта `Main::DuplicateSession()` → новый ключ, предназначенный
  именно для телефона; ключ пишется в `account.json` (и в `tdata/` как fallback).
- Android: видит `manifest.json` → ставит ключ сразу в свободный слот
  (`ConnectionsManager.importAuthKey` + `setUserId`, как уже делает `TdataImportHelper.kt:375`),
  ставит прокси аккаунта ДО первого подключения, папку, 2FA → проверяет `users.getFullUser`.
  Без повторного handoff. Нет manifest → старый путь через tdata.
- Пароля на архиве нет (решение пользователя 2026-09-29). Формат: `docs/ggtg-formats.md`.
- Запасной tdata внутри `.ggtg` не кладём: Android-импорт tdata сам дублирует сессию ещё раз.

## 3. План по шагам

Каждый этап заканчивается проверкой на реальном устройстве/эмуляторе. Порядок —
от «моста» и фундамента к фичам.

   `gradle assembleAfatDebug`/Standalone собирается и запускается на эмуляторе.

   `docs/ggtg-formats.md` — один источник правды для обеих платформ.

## 4. Риски
- Каждый дубль — новая сессия; у свежей сессии Telegram ограничивает некоторые действия
  (например, завершать чужие сессии ~24 ч). Массовые действия сразу после импорта могут падать.
- `.ggtg` = полный доступ к аккаунтам, без пароля. Не класть в облака и не пересылать.
- Android убивает фоновые задачи: без Foreground Service рассылки и массовые действия будут обрываться.
- 100 одновременно подключённых аккаунтов на телефоне — тяжело; Runner должен поднимать их по очереди.
